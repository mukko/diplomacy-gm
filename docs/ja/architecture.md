# アーキテクチャ（ドラフト）

> 英語版 [../en/architecture.md](../en/architecture.md) が正です。本書はその翻訳です。
>
> 状態: **ドラフト／提案。** *（提案）* と記した技術選定は確定ではありません。*（決定）* と記したものは確定です。

## 1. 目的

*ディプロマシー*のゲームマスターツールとして、以下を行う:

- ゲームの状態と履歴を保存する
- GM がインタラクティブな地図上で全列強の命令を入力できる
- 公式ルール（[rules.md](rules.md)、[adjudication.md](adjudication.md)）に従って命令を裁定する
- **結果と解決の手順の両方**を返し、GUI が解決をステップごとに再生できるようにする

交渉自体はツールの外（対面など）で行います。ツールは合意の履行を強制しません（R-GEN-05）。

対象範囲 *（決定）*: 標準の7人戦のみ。少人数用ルール（rules.md §14、`R-VAR-*`）には対応しない。
`variant` は常に `standard` で、サーバーはそれ以外の値を拒否する。

## 2. 構成要素

```
┌──────────────────────────┐          JSON/HTTP          ┌───────────────────────────────┐
│ GUI（Web）               │  ───── 命令 ────────────▶   │ API サーバー                  │
│  - 地図（SVG）           │                             │  - ゲーム／フェイズ管理       │
│  - 命令入力              │  ◀──── 状態・解決結果・     │  - 命令の検証                 │
│  - フェイズ／進行状況    │         トレース ───────    │  - 裁定器（純粋関数）         │
│  - ステップ再生          │                             │  - 永続化                     │
└──────────────────────────┘                             └───────────────────────────────┘
                     ▲                                                ▲
                     └────────── 共通: 型定義・マップデータ ──────────┘
```

| 構成要素 | 責務 | 技術 *（提案）* |
|----------|------|-----------------|
| `server/` | REST API、ゲームのライフサイクル、永続化、裁定器の呼び出し | **Rust**（axum、tokio、serde） *（決定）* |
| 裁定器（`server/src/engine/`） | 純粋な裁定器: `adjudicate(state, orders) → Resolution`。I/O なし。サーバーの `Adjudicator` トレイトに差し込む。 | Rust、`cargo test`。DATC ＋ [test-cases.md](test-cases.md) |
| `web/` | 地図描画、命令入力、進行状況、トレース再生 | React ＋ Vite、SVG 地図 |
| `shared/` | マップデータ（`standard.json`: 地域・海岸・隣接）。サーバーと GUI の両方が読む。GUI 用の地図描画アセット（`standard.svg`、`standard.layout.json`、`standard.graph.svg`。[map.md](map.md) §7 参照）。TypeScript のマップ型とテスト | JSON、SVG（＋ TypeScript、Vitest） |
| 永続化 | 1 ゲームにつき 1 つの JSON セーブファイル（§ 5） | ファイル *（決定）* |
| 運用 | GM のマシン上で1人で使うローカル実行。`127.0.0.1` でのみ待ち受ける。認証・ロールなし（§ 6） | *（決定）* |

裁定器が唯一の権威です。GUI は使い勝手のために事前検証してもよいが、サーバーがすべてを再検証します。

## 3. ゲームの流れ

```
ゲーム作成 ─▶ S1901M ─▶ [S1901R] ─▶ F1901M ─▶ [F1901R] ─▶ W1901A ─▶ S1902M ─▶ …
                 │            │          │           │           │
               命令          撤退       命令        撤退       建設／解散
                 └── 解決 ────┘                      └─ 補給都市更新＋勝利判定（PR-11）
```

- 合法な撤退先を持つユニットがなければ撤退フェイズ（`R`）はスキップ。
- 建設・解散が必要な列強がなければ調整フェイズ（`A`）はスキップ（PR-17）。
- フェイズは GM の操作で（または設定により全列強の提出完了時に）解決する。
  何も提出しなかった列強は R-ORD-03 / PR-09 に従って扱う。内乱は GM が宣言した場合のみ適用する（PR-16）。

### フェイズ ID 形式

`<S|F|W><年><M|R|A>` — 例: `S1901M`、`F1901R`、`W1901A`。

## 4. 中核データモデル（スケッチ）

```jsonc
// GameState（フェイズ開始時の盤面。ゲーム ID とバリアントはセーブファイル側に持つ、§ 5）
{
  "phase": "F1901M",
  "units": [
    { "power": "RUS", "type": "F", "location": "StP", "coast": "SC" },
    { "power": "FRA", "type": "A", "location": "Bur" }
  ],
  "supplyCenters": { "Par": "FRA", "Bel": null },
  "dislodged": [ /* 撤退フェイズのみ */
    { "power": "FRA", "type": "A", "location": "Bur", "attackerFrom": "Ruh", "retreatOptions": ["Gas", "Pic"] }
  ],
  "standoffProvinces": ["Sil"],
  "civilDisorder": [ { "power": "ITA", "since": "F1902M" } ],   // GM が宣言（PR-16）
  "winner": null
}

// Order（GUI から送信される構造化形式）
{ "power": "FRA", "unit": "Mar", "type": "move", "to": "Bur" }
{ "power": "FRA", "unit": "Gas", "type": "support", "target": "Mar", "to": "Bur" }   // 維持支援なら "to" を省略
{ "power": "ENG", "unit": "Nth", "type": "convoy", "target": "Lon", "to": "Nwy" }
{ "power": "ENG", "unit": "Lon", "type": "move", "to": "Nwy", "viaConvoy": true }
{ "power": "RUS", "unit": "StP", "type": "build", "unitType": "F", "coast": "NC" }

// Resolution
{
  "phase": "F1901M",
  "orders": [ { "order": { /* … */ }, "valid": true, "outcome": "success|fail|void|cut", "reason": "…", "rules": ["R-STD-01"] } ],
  "trace": [ { "step": "support-cuts", "order": "A Sil S A Pru-War", "outcome": "cut", "by": "A Boh-Sil", "rules": ["R-CUT-01"] } ],
  "nextState": { /* GameState */ }
}
```

列強 ID: `AUS ENG FRA GER ITA RUS TUR`。地域 ID: ルールブックの略称（[map.md](map.md)）。

## 5. 永続化（セーブファイル）

- **1 ゲーム = 1 つの JSON ファイル** `<dataDir>/<gameId>.json`（サーバーのオプション `--data-dir`、
  環境変数 `DIPLOMACY_GM_DATA_DIR`、既定は `data/games`）。ファイルが唯一の正です。
- **自動保存:** 変更（新規ゲーム、命令の提出、解決）のたびに即座に、アトミックに（一時ファイル＋リネーム）
  書き戻す。クラッシュしても書きかけのセーブは残らない。
- **復元:** セーブファイル（ディスク上またはアップロード）は使用前に読み込んで**検証**する: 形式とバージョン、
  ゲーム ID、既知の地域・海岸、1 地域 1 ユニット（R-UNIT-03）、履歴の整合性（各解決結果の `nextState` が
  次に記録された盤面と一致すること。ただし `civilDisorder` はフェイズの間に GM が変更できるので比較しない）。不正なデータは拒否し、何も書き込まない。
- **再生**に追加データは不要: 履歴には解決済みの各フェイズの開始時の盤面、命令、`Resolution`（`trace` を含む）が残る。

```jsonc
// <gameId>.json
{
  "format": "diplomacy-gm/game",
  "formatVersion": 1,
  "gameId": "g_…",
  "title": "金曜の対局",
  "variant": "standard",
  "createdAt": "2026-10-19T12:00:00Z",
  "updatedAt": "2026-10-19T13:10:00Z",
  "state": { /* GameState: 現在の未解決フェイズ */ },
  "orders": { "GER": [ /* Order */ ] },          // 現在のフェイズでこれまでに提出された命令（秘密）
  "history": [                                    // 解決済みフェイズ（古い順）
    { "phase": "S1901M", "state": { /* GameState */ }, "orders": { /* 列強ごと */ },
      "resolution": { /* Resolution */ }, "resolvedAt": "…" }
  ]
}
```

再生の**フレーム**は `history` の 1 要素（盤面＋命令＋解決結果）で、最後に現在の盤面のフレームが続く。
フレーム内では GUI が `resolution.trace` をステップ送りする（§ 7）。

## 6. API（スケッチ）

スタート画面: **新規ゲーム** → `POST /games`、**ロード** → `GET /games` のあと `GET /games/:id`
（またはセーブファイルを `POST /games/import`）、**再生** → `GET /games/:id/replay`。
実装済みのルートには ✔ を付けた。`resolve` は移動・撤退・調整フェイズを裁定する。

| メソッドとパス | 目的 |
|----------------|------|
| `GET  /maps/standard` ✔ | 描画とクライアント側ヒント用のマップデータ |
| `GET  /games` ✔ | 保存済みゲームの一覧（ID、タイトル、フェイズ、最終更新、新しい順）と、読み込めなかったセーブファイル |
| `POST /games` ✔ | ゲームとそのセーブファイルを作成（タイトル。今後: バリアント、列強の割り当て、設定） |
| `GET  /games/:id` ✔ | セーブファイルから復元: 現在の状態、フェイズ、提出済みの列強（命令自体は秘密のまま） |
| `GET  /games/:id/save` ✔ | セーブファイル全体をダウンロード（未解決の命令を含む） |
| `POST /games/import` ✔ | アップロードされたセーブファイルからゲームを復元（検証あり）。`?asNew=true` で新しい ID で保存 |
| `GET  /games/:id/history` ✔ | 全フェイズの命令と解決結果 |
| `GET  /games/:id/replay` ✔ | 再生フレーム（§ 5） |
| `GET  /games/:id/replay/:index` ✔ | 再生フレーム 1 つ |
| `GET  /maps/standard/svg` ✔、`…/layout` ✔、`…/graph` ✔ | GUI 用の地図描画アセット（[map.md](map.md) §7） |
| `GET  /games/:id/phases/:phase/orders` ✔ | 現在のフェイズでこれまでに提出された命令を列強ごとに返す。各命令には `PUT …/orders` と同じ `{ order, status, reason?, rules }` の検証結果が付く（ローカルの GM 用ツールのため秘匿しない）。別のフェイズを指定すると `409 phase-mismatch` |
| `GET  /games/:id/units/:prov/options` ✔ | 現在のフェイズで1つのユニットに出せる合法な命令の一覧。裁定器と同じ検証で確かめた、そのまま提出できる `Order` の形で返す。移動フェイズ: 維持、移動（分割海岸の移動先は海岸付き。輸送が可能なら `viaConvoy` 付きの候補も）、維持支援と移動支援（支援対象のユニットが合法に命令できる移動に限る）、輸送（この艦隊を通る経路がありうるものに限る）。撤退フェイズ: 撃退されたユニットの撤退先と解散。調整フェイズ: その列強に解散が必要なら解散。内乱中の列強は `civilDisorder: true` で、移動・撤退フェイズでは命令は空（命令は無視されるため、PR-16）。調整フェイズでは GM が入力できるよう解散の候補を出す（PR-08）。ユニットがなければ `404` |
| `GET  /games/:id/powers/:power/options` ✔ | 列強の全ユニットについて同じもの（撤退フェイズでは撃退されたユニット）。調整フェイズではさらに `adjustment`（補給都市数 − ユニット数）と `builds`（合法な建設すべて: 本国補給都市 × 種別 × 海岸、および建設放棄の命令）。内乱中は `builds` は空 |
| `PUT  /games/:id/phases/:phase/orders/:power` ✔ | 列強の命令を提出／置換。どの列強についても呼び出せる（内乱中の列強の解散の手動入力を含む、PR-08）。命令はすべて保存する。応答は `accepted`（件数）と `results`: 命令ごとに提出順で `{ order, status, reason?, rules }`。`status` は `valid`（書かれたとおり実行。解決時に失敗することはある）、`hold`（移動フェイズ: 実行できないためユニットは維持 — R-ORD-04）、`disband`（撤退フェイズ: 実行できないためユニットは解散）、`ignored`（効果なし: 自国のユニットでない、内乱、重複、権利を超える、フェイズ違い — PR-05/14/15/16、R-ADJ-01）。判定は裁定器の検証（adjudication.md §2）と同じ |
| `GET  /games/:id/phases/:phase/default-disbands` ✔ | 現在の調整フェイズで、解散が必要な列強ごとに `required`（必要数）、`ordered`（採用される提出済みの解散命令。GM の入力分など）、`proposed`（残りについてエンジンが解散するユニットと PR-08 の距離）を返す（R-CD-03 / PR-08 / PR-09）。`:phase` が現在のフェイズでなければ `409 phase-mismatch`、移動・撤退フェイズでは `409 not-adjustment-phase` |
| `POST /games/:id/phases/:phase/resolve` ✔ | 裁定。`Resolution`（`trace` を含む）を返し、ゲームを進める |
| `PUT  /games/:id/civil-disorder/:power` ✔ | 現在のフェイズから列強の内乱を宣言（PR-16）。`state.civilDisorder` に記録する（`since` = 現在のフェイズ）ため、セーブファイルに保存され、以後のフェイズに引き継がれ、各フェイズの開始時の盤面として履歴と再生にも残る。宣言済みなら変更なし（`changed: false`） |
| `DELETE /games/:id/civil-disorder/:power` ✔ | 現在のフェイズ以降の内乱を解除（交代プレイヤー参加時など）。解決済みのフェイズの記録には残る。宣言されていなければ `changed: false` |
| `POST /adjudicate` | ステートレス: `{state, orders}` → `Resolution`（サンドボックス、テスト、「もしも」検討） |

これらのルートの挙動 *（決定）*: 移動支援は支援対象のユニットが合法に命令できる移動に限って候補に出す。
輸送はその艦隊を通る経路がありうるものに限る。`default-disbands` は現在の調整フェイズ以外では `409` を返す。
内乱の宣言・解除を繰り返しても `200` で `changed: false` を返す。options・命令の検証・`default-disbands`
のルートは `Adjudicator` トレイトを介さず、唯一のエンジンを直接呼ぶ。

運用とアクセス *（決定）*: GM のマシン上でローカルに実行する、GM 1人用のツール。サーバーは
`127.0.0.1` でのみ待ち受け（既定値 `--addr 127.0.0.1:8080`。ループバック以外の `--addr` は起動時に拒否する）、ネットワークには公開しない。認証・
ロール・権限の制限はなく、すべてのルートをローカルの GM が使える。

秘密の同時命令（R-ORD-01）はアクセス制御ではなく運用で扱う: 命令は GM が入力し、`GET /games/:id`
は未解決の命令を返さない。他の列強の命令を画面上で隠すかどうかは GUI の表示の問題とする（§ 7）。

## 7. GUI

| 領域 | 機能 |
|------|------|
| スタート画面 | 新規ゲーム／保存済みゲームのロード（一覧またはファイルのアップロード）／ゲームの再生 |
| 地図 | SVG 地図（`standard.svg`）をメイン表示とし、補助として隣接の**グラフ表示**（`standard.graph.svg`）に切り替えられる。ユニット（A/F の形、列強の色）、補給都市の支配、分割海岸。クリックでユニット／地域を選択 |
| 命令入力 | ユニット選択 → 命令種別選択 → 対象をクリック。サーバーから得た合法な選択肢を表示。テキスト入力も可 |
| 進行状況 | 現在のフェイズ、年／季節、列強ごとの提出状況、補給都市数、タイマー（R-TURN-05）、内乱バッジ |
| GM 操作 | フェイズの解決、列強ごとの内乱の宣言／解除（PR-16）、自動選択された解散候補の確認と手動での変更（PR-08） |
| 解決の再生 | `trace` をステップ送り（前へ／次へ／再生）: 命令の強調表示、戦力、支援カット、スタンドオフ、撃退をルール ID 付きで表示 |
| 履歴／再生 | 過去のフェイズの地図と命令をフレームごとに閲覧（§ 5）。セーブファイルのエクスポート |

### 実装済みの範囲

サーバーはビルド済みの GUI（`web/dist`、`--web-dir` で変更可）を API と同じローカルのアドレスの `/` で配信する。
そのため `cargo run` ひとつで全体が起動する。開発中は `web/` で `npm run dev` を実行すると Vite が 127.0.0.1:5173 で
起動し、`/games` と `/maps` を API に中継する。

- スタート画面: 新規ゲーム、保存済みゲームの一覧、セーブファイルの読み込み（新しい ID での読み込みも可）。
- 盤面: 地図表示とグラフ表示。補給都市の支配の色分け、ユニット、撃退されたユニット。入力した命令の矢印
  （緑: 提出済みで有効、赤: 無効、灰: 未提出または他の列強）。
- 命令入力: ユニットをクリック（または一覧で選択）するとサーバーから合法な命令の候補を取得。強調表示された地域を
  クリックして移動／撤退を指定。列強ごとに提出し、命令ごとの検証結果（有効／維持に置換／無視、理由とルール ID）を表示。
  調整フェイズでは本国補給都市ごとの建設、必要な解散数、自動で選ばれる解散（PR-08）を表示。
- 進行状況: 列強ごとのユニット数、補給都市数、提出状況、内乱の宣言／解除。
- 画面内の確認を経てフェイズを解決し、解決手順をステップごとに再生（最初／前へ／次へ／最後、ステップ一覧、
  ルール ID 付きの詳細、そのステップの命令を盤面に表示、最後のステップでは解決後の盤面）。ゲームを開き直すと
  直前の解決結果を表示する。
- 撤退フェイズ: 撃退されたユニットは元の地域の横に赤い破線の枠で表示。選ぶと撤退先の候補（盤面でも強調表示）と
  解散が出る。調整フェイズ: 本国補給都市ごとの建設（種別と、サンクトペテルブルクでは海岸）、解散、建設放棄、
  自動で選ばれる解散（PR-08）。両フェイズとも、春から冬までの一巡をブラウザで確認済み。
- 履歴: **履歴**タブでゲームの全フェイズ（再生フレーム、§5）を一覧でき、選ぶ（または前へ／次へ）とそのフェイズの
  開始時の盤面を表示し、解決手順をステップごとに再生できる。
- 日本語／英語の切り替え（ブラウザに記憶）。

未対応: タイマー、命令のテキスト入力。

## 8. 開発方針

- **ルールが仕様。** エンジンのあらゆる挙動はルール ID かプロジェクト裁定（PR-xx）に遡れること。
- **エンジンはテストファースト。** [test-cases.md](test-cases.md) のルールブックの例と関連する DATC ケースを単体テストにする。
- **英語ドキュメントが正**。日本語ドキュメントはそれを反映し、同じ変更で更新する。
