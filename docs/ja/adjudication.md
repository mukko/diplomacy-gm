# 命令裁定 仕様

> 英語版 [../en/adjudication.md](../en/adjudication.md) が正です。本書はその翻訳です。

API サーバーが命令の集合を結果に変換する方法を定めます。ルール ID は [rules.md](rules.md) を参照。
実行可能な例は [test-cases.md](test-cases.md) にあります。

## 1. 概要

裁定は純粋関数です:

```
adjudicate(state: GameState, orders: Order[]) -> Resolution
```

- `state` — フェイズ（`S1901M` …）、ユニットの位置（海岸付き）、補給都市の支配、撃退されたユニット（撤退フェイズ）。
- `orders` — ユニット1つにつき最大1命令。命令した列強が紐づいている。
- `Resolution` — 命令ごとの結果、GUI 用の**ステップごとのトレース**、次の `GameState`。

フェイズ種別ごとに裁定器が異なります:

| フェイズ種別 | 入力 | 出力 |
|--------------|------|------|
| 移動 (`M`) | 維持／移動／支援／輸送 | 新しい位置、撃退されたユニットとその合法な撤退先 |
| 撤退 (`R`) | 撤退／解散 | 新しい位置。秋の後は補給都市支配の更新と勝利判定 |
| 調整 (`A`) | 建設／解散／建設放棄 | 新規ユニット、除去ユニット |

裁定器は**決定的**でなければならず、命令の入力順に依存してはいけません。

## 2. 命令の解析と検証

検証は解決の**前**に行います。無効な命令は**維持**に置き換えられ（R-ORD-04）、理由がトレースに記録されます。

### 2.1 解析（テキスト入力）

GUI は構造化された命令を送信しますが、利便性とテストのためにテキストパーサーも提供します。

- 大文字小文字を区別しない。ユニット種別（`A`/`F`）は省略可（R-ORD-06）。指定されていて誤っている場合は無効。
- 移動の区切り: `-`、`–`、`->`、`to`。キーワード: `H`/`Hold(s)`、`S`/`Support(s)`、`C`/`Convoy(s)`、
  `R`/`Retreat`、`D`/`Disband`、`B`/`Build`、`via convoy`。
- 海岸: `NC SC EC`、および `/nc`、`(nc)`、`North Coast` など。
- 地域の別名（入力時に受け付け、ルールブックの略称に正規化）: 例 `Lyo`→`GoL`、`Mao`/`Mat`→`Mid`、
  `Nao`→`NAt`、`Nwg`→`Nrg`、`Stp`→`StP`、`Naf`→`NAf`、`Port`→`Por`、正式名称。
- 曖昧なものはすべて無効（「迷ったら略さず書け」）。

### 2.2 検証ルール（移動フェイズ）

| チェック | 失敗時 |
|----------|--------|
| その位置にユニットが存在し、命令した列強のものである | 命令を無視（PR-14） |
| 移動: その種別／海岸で目的地に隣接している（R-MOV-01/02）、または陸軍で輸送経路があり得る（R-CVY-03） | 維持 |
| 分割海岸の地域への移動で、到達可能な海岸が2つあり海岸指定がない | 維持（R-MAP-07） |
| 到達できない海岸を指定した移動 | 維持（PR-04） |
| 支援: 支援するユニットが支援先の地域へ移動可能（R-SUP-02/03） | 維持 |
| 支援: 支援対象の位置にユニットが存在する | 維持 |
| 輸送: 命令ユニットが海域にいる艦隊（R-CVY-01）、輸送対象が陸軍（R-CVY-02） | 維持 |
| 輸送: 出発地と目的地が沿岸地域 | 維持 |

注:「支援／輸送が実際の命令と一致しない」ことは検証失敗**ではありません**。命令自体は合法で、解決時に
何も提供しないだけです（R-SUP-06、R-CVY-04）。

## 3. 解決アルゴリズム（移動フェイズ）

標準的な**決定 (decision) ベース**の手法（L. B. Kruijswijk の *The Math of Adjudication* で説明され、
現代の多くの裁定プログラムが採用）を使い、DATC（Diplomacy Adjudicator Test Cases）で検証します。
ルールブックのルールは以下の定義に対応します。

### 3.1 決定事項

各命令について裁定器が決定するもの:

| 決定 | 対象 | 意味 |
|------|------|------|
| `path` | 移動 | 陸軍の移動に有効な経路がある（隣接、または撃退された艦隊のない輸送経路が1つ以上） |
| `support` | 支援 | 支援が*与えられる*（カットされず、無効でもない） |
| `move` | 移動 | 移動が成功する |
| `dislodged` | 全ユニット | ユニットが撃退される |

### 3.2 戦力

| 戦力 | 定義 |
|------|------|
| 地域 P の**維持戦力** (hold strength) | P が空、または P のユニットが移動に成功して去った場合は 0。P のユニットが移動を試みて失敗した場合は 1。それ以外は 1 ＋ 与えられた維持支援の数。 |
| 移動 X→P の**攻撃戦力** (attack strength) | `path` がなければ 0。P が空、または P のユニットが移動に成功して去る（かつ X と正面衝突していない）場合: 1 ＋ 与えられた支援数。それ以外: P のユニットが X と同じ列強なら 0（R-SLF-01）。異なれば 1 ＋ **P の所有者からの支援を除いた**支援数（R-SLF-02）。 |
| 移動 X→P の**防御戦力** (defend strength、正面衝突時のみ) | 1 ＋ 与えられた支援数。 |
| 移動 X→P の**阻止戦力** (prevent strength) | `path` がなければ 0。X が正面衝突していて相手の移動が成功した場合は 0（R-STD-07）。それ以外は 1 ＋ 与えられた支援数（自国からの支援もここでは算入 — PR-02）。 |

### 3.3 決定ルール

- **移動 X→P が成功する** のは次の両方を満たすとき:
  - 攻撃戦力 > P の維持戦力 — 正面衝突（P のユニットが輸送なしで X へ移動する）の場合は、攻撃戦力 > 相手の移動の防御戦力。**かつ**
  - 攻撃戦力 > P への他のすべての移動の阻止戦力。
- **支援がカットされる**（R-CUT-01〜04）のは、支援ユニットが撃退された場合、**または** 支援ユニットの地域への、
  `path` が有効な移動であって
  - 支援ユニットと異なる列強からのもの（R-CUT-04）であり、
  - 支援先の地域から来たものではなく（R-CUT-01）、
  - 輸送された攻撃の場合は R-CVY-09（攻撃者の輸送に必要な艦隊への攻撃を支援している）で除外されないもの（ただし R-CVY-10 に該当する場合を除く）
  が存在する場合。
- **ユニットが撃退される** のは、そのユニットが移動に成功せず、その地域への移動が成功した場合。
- **輸送経路が存在する** のは、命令が一致し、かつ撃退されていない輸送艦隊の連鎖が出発地と目的地を結んでいる場合
  （R-CVY-03/05/08）。陸路と輸送の選択: R-CVY-11 / PR-07。
- **輸送なしの正面衝突** とは、2ユニットが互いの地域へ、どちらも陸路（艦隊は通常移動）で移動しようとする状況（R-STD-04）。
  どちらかが輸送を使う場合は独立した移動として扱う（R-CVY-07）。

### 3.4 循環とパラドックス

決定は互いに依存します。推測と検証による再帰（または不動点までの反復）で解決します。依存の循環が見つかった場合:

1. **循環移動**（A→B→C→A、すべて陸路、正面衝突なし）— すべて成功（R-STD-05）。
2. **輸送パラドックス** — まず R-CVY-09/10（ルールブック自身の解決方法）を適用。
3. それでも残る**パラドックス** — *Szykman ルール* を適用: 関係する輸送陸軍は移動せず、何の効果も持たない
   （支援をカットせず、スタンドオフも起こさない）。PR-03 参照。

### 3.5 移動フェイズの出力

- 撃退されなかった全ユニットの新しい位置。
- 撃退されたユニットごとに: 攻撃者の出発地と、この時点で計算した**合法な撤退先**（R-RET-02/03/04）
  — そのユニット種別／海岸で到達可能な隣接地域から、占有地域・攻撃者の出発地・このターンにスタンドオフが起きた地域を除いたもの。
- `standoffProvinces`: スタンドオフにより空いた地域（R-RET-03(c) に必要）。
- 撃退されたユニットがない、またはどれにも合法な撤退先がない場合、撤退フェイズはスキップされる。

## 4. ステップごとのトレース（GUI 用）

GUI は解決を1ステップずつ再生できなければなりません。そのため裁定器は、命令・地域・ルール ID を参照する
**トレースステップ**の順序付きリストを出力します。内部アルゴリズムは再帰的なので、トレースは解決後に計算する
*表示順序*です:

| # | ステップ | 内容 |
|---|----------|------|
| 1 | `validate` | 各命令: 有効／維持に置換。理由とルール ID |
| 2 | `convoy-routes` | 輸送陸軍ごとの経路候補と採用経路（陸路／輸送、R-CVY-11） |
| 3 | `support-cuts` | 各支援: 有効／カット（誰による・どのルール）／無効（不一致） |
| 4 | `strengths` | 争われる地域ごと: 維持／攻撃／防御／阻止戦力と寄与した支援 |
| 5 | `moves` | 各移動: 成功／失敗と決め手となった比較（例: "2 > 1"、"スタンドオフ 1 = 1"） |
| 6 | `dislodgements` | 撃退されたユニット、攻撃者の出発地、撤退先候補 |
| 7 | `result` | 最終位置、スタンドオフ地域 |

撤退・調整フェイズも同様の短いトレースを出力します（`validate`、`conflicts`、`result`、秋の場合は `sc-ownership`、`victory-check`）。

各トレース項目には根拠となるルール ID を含めます。例:
`{ "step": "support-cuts", "order": "A Sil S A Pru-War", "outcome": "cut", "by": "A Boh-Sil", "rules": ["R-CUT-01"] }`

## 5. プロジェクト裁定（曖昧点と未定義事項）

ルールブックに記述がない、または曖昧な点についての決定です。変更する場合は本表（および英語版）と関連テストを
更新してください。**(未確定)** の項目はプロジェクトオーナーの確認が必要です。

| ID | 論点 | 裁定 | 根拠 |
|----|------|------|------|
| PR-01 | 支援付きの正面衝突 | 強い側が勝ち、相手を撃退する。同戦力なら両者その場に留まる。 | ルールブック図13–14、DATC |
| PR-02 | 防御側と同じ列強からの支援 | その列強のユニットの撃退には算入しないが、阻止戦力（他ユニットとのスタンドオフ）には**算入する**。 | 図24–26 |
| PR-03 | 規則21–22でカバーされないパラドックス | Szykman ルール: 関係する輸送陸軍は移動せず効果も持たない。 | DATC 推奨 |
| PR-04 | 海岸指定 | 省略されていても到達可能な海岸が1つなら推定する。到達不能な海岸の指定は無効（維持）。陸軍命令の海岸指定は無視。 | R-MAP-07 |
| PR-05 | 1ユニットへの複数命令 | 発生しない: API はユニットごとに1命令を保存し、再提出で置き換える。 | — |
| PR-06 | **輸送された**攻撃者の出発地への撤退 | ルールブックの文言（R-RET-03(b)）どおり**禁止**。DATC では許可されているが採用しない。プロジェクトオーナー確認済み。 | R-RET-03 |
| PR-07 | "via convoy"（輸送経由） | 移動命令の `viaConvoy: true` で表す。目的地が隣接していない場合は指定に関係なく輸送を使う。 | R-CVY-11 |
| PR-08 | 内乱時の距離 **(未確定)** | ユニットから自国のいずれかの本国補給都市までの最小地域ステップ数。ユニット種別に関係なく陸・海どの地域も通過可能として数える。 | R-CD-03 |
| PR-09 | 撤退・調整命令の未提出 | 撤退未提出 → 解散。必要な解散の未提出 → R-CD-03 で選ぶ。建設未提出 → 放棄。 | R-RET-07, R-CD |
| PR-10 | 脱落 | ユニットも補給都市もない列強は脱落。補給都市があってユニットがない列強はゲームに残る。 | — |
| PR-11 | 勝利判定のタイミング | 秋の撤退フェイズの後、補給都市支配の更新後、調整の前に判定。 | R-GEN-03 |
| PR-12 | 一致しない輸送命令 | 何も提供しない。その艦隊は移動していない扱い（維持支援を受けられる）。 | R-CVY-04 |
| PR-13 | 移動命令が無効だったユニットへの維持支援 | 有効 — そのユニットは維持として扱われる。 | R-ORD-04, R-SUP-05 |
| PR-14 | 所有していない／存在しないユニットへの命令 | 無視し、トレースに報告する。 | — |
| PR-15 | 過剰・不正な調整命令 | 不正なものは無視（R-ADJ-01）。権利を超える建設は提出順に無視。占有中または非支配の本国補給都市への建設は無効。 | R-ADJ |
| PR-16 | 内乱の発生条件 | **GM が宣言する**（自動判定はしない）。GM はツールに宣言（列強・開始フェイズ）を入力し、後で解除できる（例: 交代プレイヤーの参加）。宣言中は、移動フェイズ — 命令はすべて無視し全ユニット維持、相互支援なし（R-CD-01）。撤退フェイズ — 撃退されたユニットは解散（R-CD-02）。調整フェイズ — 建設なし、必要な解散は R-CD-03 で選ぶ。宣言なしで単に命令を提出しなかった列強は R-ORD-03 / PR-09 で扱う。 | R-CD-01, R-CD-02 |

## 6. 撤退フェイズ

1. 検証: 撤退先はそのユニットの事前計算済み撤退先に含まれていなければならない。含まれなければ解散。
2. 2つ以上のユニットが同じ地域へ撤退した場合 → すべて解散（R-RET-06）。
3. 適用する。**秋**の撤退フェイズの後: 補給都市の支配を更新（R-SC-01/02）し、勝利を判定（PR-11）。

## 7. 調整フェイズ

1. 各列強について `delta = 支配補給都市数 - ユニット数`。
2. `delta > 0`: 有効な建設を最大 `delta` 個受け付ける（R-ADJ-03/04/05/06）。それ以外は無視。
3. `delta < 0`: ちょうど `-delta` 個の解散が必要。不足分は R-CD-03 で選ぶ（PR-09）。
4. `delta = 0`: 命令は受け付けない。
5. 次のフェイズは翌年の春。
